Three implementation approaches

All three deliver the same user experience. They differ in how much new infrastructure we add vs. reuse existing Supabase assets.

1

Maximalist — new MVs + new routes

New funding_galaxy_nodes and funding_galaxy_edges materialized views purpose-built for the galaxy. New signal_patterns table modeled after FOIA Fluent. Six new API routes under /api/galaxy/*.

Pros: Cleanest separation. Fastest queries. Cons: Two new MVs to maintain/refresh. Duplicates work the existing money_flow_edges MV already does. ETL complexity increases.

2

Minimalist — client-side transform, no new tables

Reuse money_flow_edges MV unchanged. Transform to galaxy node/edge format on the client. Store AI patterns in localStorage (hacky) or a tiny funding_flow_patterns table.

Pros: No backend changes for galaxy data. Cons: Ships 10-50k raw edges to browser on every visit (bandwidth). Client-side aggregation blocks the render thread. No server-side filtering. Doesn't scale.

3

Hybrid — reuse MV, add thin pattern layer ★ recommended

Keep money_flow_edges as source of truth. Add one new table: funding_flow_patterns (mirrors FOIA Fluent's signal_patterns schema). Add three new routes: /api/galaxy/universe, /api/galaxy/sector/:name, /api/galaxy/employer/:id, plus /api/galaxy/patterns. Each route queries the existing MV + joins patterns where relevant.

Pros: Minimal new infra. Server does aggregation/filtering (fast). Patterns live next to their evidence. Clear API contract. Easy to extend. Cons: Slight query duplication with existing donor routes — acceptable because shapes differ (galaxy needs node/edge, Sankey needs source/target/amount tuples).

Recommendation: Approach 3

One new table, four new routes, no new MVs. Reuses your already-indexed money_flow_edges (with its pre-aggregated 5-tier structure). Matches the pattern from FOIA Fluent closely enough that research carries over, but doesn't duplicate your existing ETL. The weekly pattern cron writes to funding_flow_patterns; the frontend queries one endpoint per view mode and gets exactly the nodes/edges it needs.
